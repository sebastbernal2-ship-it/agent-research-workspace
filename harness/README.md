# Local harness prototype

A **working offline composition prototype, not yet a production harness**. Complete upstream source snapshots for AG2, AgenticX, and Meldwork are vendored under `../spikes/*/upstream/`; their pinned source revisions and composition boundaries are documented in the spike READMEs. Product adapters invoke Meldwork V4's collaboration runtime, AgenticX's worker executor, and AG2's message/network protocol while project state remains canonical here.

## Data flow

```text
AG2 v1.0 Network/WAL ──listener + replay──┐
                                          ├─> canonical SQLite events + content-addressed blobs
AgenticX 0.6.5 Executor ──JSON subprocess─┘

Meldwork V4 receipt + public committed text ──Node parser/sanitizer adapter──> same event contract/store
```

AG2 owns message transport/turn order; AgenticX executes one bounded worker task in its own venv; Meldwork's pinned V4 parser/sanitizer validates receipt-shaped data. The SQLite store, not any candidate's internal DB, is canonical for the prototype.

## What currently works (offline, deterministic)

- SQLite event append validates the v0.1 JSON Schema, assigns per-project sequence in a transaction, enforces event/idempotency uniqueness, rejects ordinary update/delete, stores content-addressed blobs and immutable record snapshots, supports atomic multi-event commits, hash-chains events, verifies/reopens, exports JSONL, and creates a verified SQLite backup containing source blobs, staged adapter receipts, and durable queue state. A subprocess killed after the first uncommitted batch insert recovers with no partial rows. Project control/capability commands append against the sequence of the verified state snapshot; a stale command loses with `ConcurrentWriteConflict` rather than appending an invalid transition.
- `ModelRouter` resolves role defaults and project/role overrides through a normalized provider protocol, with no implicit failover, an injected invocation-policy seam, and a deterministic mock provider. Its tests make no model/network calls; fake policies do not authenticate or authorize real use.
- A framework-neutral UI and Python standard-library service in `../ui/prototype/` provide a loopback-only vertical slice over one seeded synthetic project. Project/work/inbox reads come from canonical SQLite; answer/reject commands persist and survive restart. The fixed synthetic principal is not real authentication; VP chat/model assignments remain unconnected and no tools/providers are available.
- `RunLedger` records each assigned agent/adapter run with a context hash and terminal status in canonical events. Starting the first root run on ready work atomically changes it to running, and concurrent root ownership is rejected; queued root starts additionally validate the active lease in the same SQLite transaction and persist the job/generation link; delegated children require an active parent in the same run tree. Orphaned `running` work requires recovery/requeue. Optional parent-run links are checked during replay, require a shared correlation ID, and prevent a parent from finishing before active children. Messages, artifacts, and evidence can be attributed to the producing run; run-finish snapshots capture output IDs, artifact/source hashes are checked, and artifact input-artifact/evidence derivation links must resolve to registered records in the same work or its dependency closure. Restart recovery closes runs leaf-first as `interrupted`; linked outputs can be verifier-reconciled without re-executing the adapter. Non-empty capability grants are rejected because no production capability executor is connected.
- `EvidenceRegistrar` accepts already-retrieved source bytes (5 MiB default cap), records an HTTP(S) source URI without dereferencing it, stores the snapshot as a content-addressed blob, and appends claim-linked evidence with run attribution and idempotent retries. It rejects URI credentials/fragments and oversized snapshots. This provides byte integrity and traceable registration, not source authenticity, trustworthiness, or a network fetcher.
- `OrganizationCoordinator` provides reusable single-work lifecycle gates plus deterministic sequential `run_plan` scheduling over the canonical dependency DAG. It handles dependency/inbox pauses, verifier-gated completion, explicit user-authorized requeue with a fresh run ID, cancellation and adapter failures with leaf-first descendant interruption, and recovery without implicit adapter replay. A callback that returns while delegated child runs remain active fails closed. `run_queued` now claims and heartbeats a queue lease, resolves callbacks only through a trusted caller factory, and returns blocked jobs to the queue for readiness re-check and fresh run generations after inbox answers. A supervised `serve_queue` polling loop now runs locally; a stop request prevents another claim and drains an already-claimed job. Forced task cancellation records canonical run/work cancellation and closes the queue job as failed when that state is verified; a partial or stale-lease cancellation remains recovery-required. Callback registrations are still re-created by trusted startup code, and there is no deployed service/health lifecycle or distributed transaction. See [`../design/ORCHESTRATION_CONTRACT.md`](../design/ORCHESTRATION_CONTRACT.md).
- `SQLiteWorkQueue` persists bounded v1 execution descriptors (trusted route key, agent/verifier/adapter identity, context hash, correlation, optional parent) in the same SQLite backup, enforces one open job per project/work item, and offers cross-process claim/renew/release with random lease tokens and increasing generations. `OrganizationCoordinator.run_queued` consumes these jobs through a re-registered trusted factory and requires a fresh run ID per generation. Claims re-check canonical dependency, inbox, and run readiness; blocked jobs wait in the queue and resume after canonical state changes. Run-attributed canonical appends and adapter-receipt staging check persisted lease generation/state, so a worker is rejected after the queue records expiry/recovery or a newer generation; queued run bindings are checked against canonical history during backup verification. Expired claims enter `recovery_required` and require an explicit no-live-worker attestation before safe requeue; terminal canonical work failures/cancellations close the queue job instead of leaving an unclaimable queued row. This is operational metadata, not canonical project state. This is not an expiry-time/side-effect fence: the queue must first observe expiry, the attestation is unauthenticated, external effects are not fenced, and callbacks are not persisted.
- `InboxReadModel` projects project-scoped question summaries, priority/status filters, exact affected-work status, a record detail/history view, and an ETag-like hash. Detail and history are derived from one verified event snapshot to avoid mixed-revision reads. `InboxApplication` wires it to answer/reject/cancel commands with mandatory ETags and injected principal/project-access interfaces; tests use fake providers/policies only. `ProjectApplication` similarly gates project/work reads and commands, and now provides separately permissioned project-scoped reads for runs, evidence, artifacts, discussion messages, and capability grants; it derives creator/event actors from an injected principal, restricts human transitions to approve/cancel bound to the caller's expected work revision (replayed stale approvals conflict), and routes capability grant/revoke through the same membership check while deriving the approver identity. These framework-neutral boundaries do not authenticate sessions; the loopback UI still uses a fixed fake identity.
- The local control plane creates and revises projects/work through immutable snapshots, checks parent/dependency references and rejects cycles, and freezes the dependency closure of work under an open blocking question. A work item cannot enter `running` or receive capability authorization until each explicit dependency is `completed`; replay independently rejects forged start events. It keeps human questions outside discussion threads, pauses only the explicit affected IDs, and commits a user's answer plus exact resume set atomically. Rejected/cancelled/expired questions leave blocking work `blocked`; supersession carries the exact pause set.
- A small capability authority atomically records explicit user-actor grants and work references, revocation, expiry (maximum seven-day prototype TTL), and exact project/work/agent/action/opaque-resource checks. Tests deny cross-project, wrong-subject, wrong-action/resource, expired, revoked, forged-event and non-runnable-work access. A test-only guarded executor proves denied requests do not invoke an in-memory callback; it does not run real tools or external effects and is not authenticated identity or production enforcement.
- A separate synthetic alignment-memory contract/evaluator covers provenance, scope, user confirmation, expiry, corrections, and conflicting confirmed constraints. It can flag a conflict and request clarification, but it does not authorize actions, rewrite project truth, or import private user data.
- A deterministic reference projector reconstructs project/work/run/question/capability/artifact/evidence/message state. Tests cover restart/export, failed runs, contradictory evidence preservation, evidence snapshot registration, artifact-content tampering and derivation links, forged transitions, dependency cycles/closures, and append contention.
- AG2's real in-process round-robin Hub accepts proposal → AgenticX critique → specialist revision. The AgenticX task runs in a separate process using the pinned AgenticX venv, temporary HOME/cwd, restricted environment, no tools, an injected deterministic provider response, a 30 KB request cap, 64 KB stdout/16 KB stderr caps, and a timeout. Protocol-error and output-flood paths are tested; timeout kills the worker process group on POSIX (and the direct child elsewhere). This still is not a hardened sandbox.
- AG2's durable DiskKnowledgeStore WAL can be reopened; a new mirror instance can replay it into canonical SQLite without duplicate events. An injected canonical-append outage is observed as mirror degradation and repaired by replaying the accepted AG2 WAL, preserving already-mirrored messages without duplicates. The end-to-end AG2 + AgenticX integration also passes restart/replay.
- The Meldwork adapter calls the pinned V4 receipt parser and sanitizer in a Node subprocess with a 60 KB input cap, 2 MB stdout cap, 16 KB stderr cap, and timeout; it maps supported phases to the shared discussion-event contract, persists sanitized content, and rejects invalid receipts. For canonical run assignments, SQLite records a stable invocation before dispatch, binds queued invocations to job/generation, rechecks the live queue lease atomically when marking an invocation executing, stages the validated receipt, and atomically imports its event batch while marking the invocation imported under the active queue lease. Exact retry after a lost commit response deduplicates without rerunning the adapter; a dispatched invocation with no staged receipt is marked ambiguous and is not auto-replayed. A staged queued-run receipt left by a crash requires explicit no-live-worker recovery naming its matching expired job before import and run interruption. Queue lease verification covers the dispatch transition, not an external effect that continues after dispatch; this is not a distributed transaction or adapter-side outbox.
- A full offline V4 integration runs Meldwork's real Node `LocalWorkspace` orchestration with eight deterministic AgenticX `AgentExecutor` subprocess calls. The Node orchestration response is capped at 2 MB stdout/16 KB stderr with a timeout; its proposal/challenge/work/synthesis/verification receipts pass the pinned V4 parser/sanitizer and replay from the same canonical log. Output-flood rejection is tested. It does not run Electron or call a real model.
- One end-to-end offline organization run combines a blocking human inbox gate, parent/child work and run DAGs, coordinator-driven dependency scheduling, AG2 orchestrator proposal → AgenticX subprocess critique → specialist revision, and the real pinned Meldwork V4 `LocalWorkspace` flow with eight deterministic AgenticX worker calls. Meldwork's supported verification receipt gates completion; all eleven discussion/phase messages are linked to one of six parent-linked runs, with run-finish output IDs checked on replay. The exact resumed work set and final work states replay after restart with the AG2 WAL deleted. No model API, external source, private data, or tool is used; this is an integration proof, not validated agent quality or a production scheduler.

These tests prove protocol, adapter, persistence and deterministic mock execution paths—not real-model reasoning quality, product safety, or alignment.

## Reproduce

From the repository root:

```bash
python3 -m pip install -r contracts/requirements-test.txt
python3 -m unittest discover -s contracts/tests -v
python3 -m unittest discover -s harness/tests -v
python3 -m unittest discover -s alignment/tests -v
python3 -m unittest harness.integration_tests.test_meldwork_bridge -v
python3 -m unittest harness.integration_tests.test_meldwork_agenticx_runtime -v
```

The AG2 venv is pinned/isolated under its spike; install the schema test dependency there once if needed, then run:

```bash
uv pip install --python spikes/ag2-collaboration/.venv/bin/python 'jsonschema>=4.10,<5'
spikes/ag2-collaboration/.venv/bin/python -m unittest \
  harness.integration_tests.test_ag2_mirror \
  harness.integration_tests.test_ag2_agenticx \
  harness.integration_tests.test_offline_organization_run -v
```

`harness/tests/test_agenticx_bridge.py` launches the ignored AgenticX spike venv automatically. The full Meldwork/AgenticX runtime integration launches the pinned Meldwork V4 Node runtime and AgenticX spike venv; it uses only deterministic mock responses, not Electron or a model API. Meldwork parser-only tests require Node.js and the vendored source snapshot.

## Current limits / known failure surfaces

- This remains a prototype. No production web UI or authenticated HTTP service exists. The loopback-only server in `../ui/prototype/` exposes one synthetic project with a fixed fake principal; it requires ETags on inbox commands but is not real authentication and must not be exposed to a LAN/proxy. VP/model connections, production autonomous scheduler, multi-laptop worker, and deployment service do not exist. The local `run_plan` consumes caller-declared work callbacks sequentially, but callback registrations are not persisted; the durable SQLite queue has a supervised polling loop but no deployed service/health lifecycle or persisted trusted callback registry. Run-attributed canonical writes are checked against persisted job state/generation after the queue observes lease expiry; the expiry-to-recovery race, non-attributed writes, and tool/external side-effect boundaries are not fully fenced. Adapter-side outboxes, exactly-once effects, and remote cancellation are still absent. A canonical SQLite invocation journal/receipt inbox is implemented for the Meldwork bridge only. The inbox/API design in `design/INBOX_API.md` distinguishes that local adapter from the intended service; notification UX and durable scheduler continuations are absent. Capability actor fields are caller-supplied (not authenticated); only a test-only in-memory callback passes through the guard, with no actual adapter/tool integration. The local sequence check prevents stale command writes, and answer/closure commands compare the inbox ETag from the same verified snapshot. The demo's fake identity is not a security boundary. It is not a sandbox or TOCTOU-safe side-effect boundary. Dependency revisions are locally validated/frozen under blocking questions; remote concurrency is untested.
- The reference projector covers the current closed v0.1 event vocabulary; a written migration policy exists, but no migration dispatcher/second-version test exists. Independent contract review, process-level concurrency/crash fault injection, and production-store decision remain. Contract issue #2 remains open.
- AG2's HubListener is observational and deliberately swallows listener exceptions. The mirror records degradation and exposes it to the caller; WAL replay repairs missed events only while the AG2 WAL still exists. This is not an atomic dual-write/outbox guarantee; the SQLite invocation journal currently covers only the run-assigned Meldwork receipt path. Issue #3 remains open.
- Current AG2 tests use local transports and no external network auth. The AG2 subprocess/adapter path has no production identity boundary yet.
- AgenticX's bridge proves one deterministic AgentExecutor request over stdio with bounded request/stdout/stderr bytes and timeout. The worker is process-isolated, **not a hardened sandbox**; POSIX timeout/overflow kills its process group, while other platforms currently kill only the direct child. No Studio API/server, real model, persistent AgenticX session, tools, or approval resume was exercised. Issue #4 remains open.
- The Meldwork runtime bridge runs the actual Node `LocalWorkspace` V4 orchestration, but not the Electron application or a model-backed agent. Its AgenticX workers and V4 receipt contents are deterministic mocks. Apple-silicon app behavior and the pinned NPM audit findings remain unresolved. Issue #5 remains open.
- This local harness makes no provider/model calls. General provider-call approval has been given, but the current reliability and provenance work needs none; any model-quality pilot still needs an explicit model/provider, spend cap, data scope, credentials and terms review. HiperGator policy/deployment is tracked separately in issue #9 and does not block local integration.

Treat errors as component-local until traces prove otherwise: AG2 transport/WAL, AgenticX subprocess/JSON, Meldwork receipt parser, canonical schema, SQLite append/hash chain, or recovery/replay. Keep the raw candidate stores exportable and inspectable while debugging; do not hide adapter errors as successful runs.
