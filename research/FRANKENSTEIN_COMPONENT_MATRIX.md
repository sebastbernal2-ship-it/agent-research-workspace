# Frankenstein component matrix: reuse by capability, not by product

**Purpose:** Turn the existing candidate research and local adapter evidence into concrete reuse decisions. “Frankenstein” means composing selected components behind contracts—not merging repositories, sharing their databases, or declaring a single candidate the platform.

**Evidence rule:** Separate (1) source/README claims, (2) upstream tests, (3) our deterministic adapter tests, and (4) real-model/product evidence. We currently have no real-model quality evidence, production deployment, authenticated multi-user service, or approved external execution.

## What “grab and use” means in practice

**Already used narrowly:**

- AG2 Network for local message/channel flow and WAL replay.
- AgenticX `AgentExecutor` for bounded deterministic specialist calls.
- Meldwork V4 `LocalWorkspace` for deterministic collaboration/work/verification behavior and validated receipt import.
- Our own project/work/question/run contracts and local `OrganizationCoordinator` for durable ownership and lifecycle decisions.

**Vendored for evaluation but not product-integrated:**

- NAC (`arcee-ai/nac`) source snapshot; not built or executed in this environment.

**Other researched candidates not vendored or product-integrated:**

- AgenticX Studio's full server, group-workforce runtime, memory, sandbox, observability, or gateway.
- Meldwork's full Electron product, UI, local stores, scheduler/connectors, or packaged macOS experience.
- CrewAI, LangGraph, Temporal, Hatchet, Letta, Letta Code, OpenClaw, CAMEL-AI OWL, Orkas, MCP, or A2A runtime components.
- Production identity, tool execution, worker fleet, remote scheduler, or a production UI/service.

## Recommended sequence

1. **Reconciliation/outbox and provenance (partially implemented):** run-linked output attribution, output IDs, hash checks, artifact derivation links, a bounded source-snapshot registrar, verifier-only recovery, and a canonical-side Meldwork invocation journal/receipt inbox are tested. Staged receipt import and imported-state transition are one SQLite transaction; ambiguous dispatched calls are not replayed, and staged receipts import before run interruption. Next add authorized source retrieval/review and an adapter-side durable receipt/idempotency handshake for external effects; broaden candidate crash-point testing. Explicit retries still use fresh run IDs and are not exactly-once.
2. **AgenticX capability gap:** test its Studio GroupChatRouter/Workforce path through a small disposable adapter and compare it to the current coordinator. Record where it adds value and what it cannot do (especially peer challenge/revision and recovery). Keep all responses deterministic.
3. **Human/network seam:** test AG2 `HumanClient`/human-input suspension against our separate inbox; ensure answering resumes only canonical dependent work, not an AG2 session treated as truth.
4. **Choose one workflow comparison only if justified:** baseline our coordinator against LangGraph for graph/checkpoint semantics. Consider Temporal or Hatchet only if cross-process waits/leases/worker recovery remain unmet; do not prototype all three in parallel.
5. **Tool boundary before protocol:** implement/review actual capability enforcement, then a synthetic read-only MCP example. A2A is later, only if cross-vendor agent exchange is a real requirement.
6. **Memory/UI candidates later:** if explicitly prioritized, test Letta with synthetic read-only memory and compare to the project-owned provenance ledger; review candidate UI links/licenses before selecting anything.
7. **Keep approvals separate:** the user has granted general approval for provider calls if useful; none are needed for the present deterministic reliability work. A real-model pilot still needs a selected provider/model, spend cap, data scope, credential setup and terms review. Private profile, external tool, LAN service and HiperGator use remain behind their own approval/security/policy gates.
